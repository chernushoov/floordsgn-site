## 0. КОНТЕКСТ — обязательно прочитать перед началом

`floordsgn.netlify.app/configurator.html` — интерактивный WebGL-конфигуратор. Пользователь выбирает напольное покрытие из списка слева → видит **плиту 300×300 мм** в виде разреза с подписанными слоями. Может вращать камеру, переключать виды (Solid / Layers explode / Top-down / Reset), менять цвет покрытия.

**Текущая проблема:** плита одна и та же для всех материалов — 5 фиксированных слоёв (substrate, primer, mesh, body, topcoat) с одинаковыми пропорциями. Это враньё:
- Микроцемент в реале 2-3 мм, в модели показан как 12 мм.
- Декоративный бетон 40-80 мм, показан как 12 мм.
- 8 из 10 материалов не используют стеклосетку, но она в модели всё равно есть.
- Reciclirovанный PU-pad под ComfortFloor засунут в слот «primer» — он туда не относится.

**Задача:** сделать 10 правильных GLB-моделей, по одной на материал, с реальными пропорциями и составом слоёв.

**Что увидит конечный пользователь:** заказчик пола (девелопер / архитектор / частный клиент). Уровень доверия к сайту = уровень доверия к нам. Если он увидит микроцемент в 12 мм, он закроет вкладку.

## 1. ТЕХНИЧЕСКИЕ ОГРАНИЧЕНИЯ — нерушимо

### Формат и движок
- **Выходной формат:** glTF 2.0 binary (`.glb`), один файл на материал. Итого 10 файлов.
- **Движок:** Three.js r158 (WebGL renderer)
- **PBR-материал:** `MeshStandardMaterial` (metalness/roughness workflow). Diffuse + Normal + Roughness + AO в отдельных текстурах.
- **Цветовое пространство текстур:** diffuse — sRGB, normal/roughness/AO — linear (NoColorSpace).
- **UV:** 2 канала UV. Канал 1 — для diffuse/normal/roughness. Канал 2 — для AO map. Three.js r158 читает AO именно из uv2.

### Габариты плиты
- **Видимая поверхность:** ровно 300×300 мм (это эталонный размер sample-tile для индустрии). Менять нельзя.
- **Общая высота плиты:** определяется суммой реальных слоёв материала (см. раздел 4). НЕ нормализовать к 26 мм как сейчас.
- **Внешний скос (bevel) по краю верхней поверхности:** 1.5-2 мм, мягкий. Это то что видно когда плита под углом.

### Иерархия объектов в Blender (КРИТИЧНО для интеграции)

Структура каждого `.glb` (имена обязательны буква-в-букву, регистр важен):

```
plateRoot                       (Empty / Armature root, origin в центре верхней грани, 0,0,0)
├── topcoat                     (Mesh — верхний слой, лак/sealer)
├── body                        (Mesh — основное тело покрытия)
├── mesh-layer                  (Mesh — стеклосетка/армирование. ОПУСТИТЬ если у материала нет mesh в buildup)
├── membrane                    (Mesh — мембрана/акустический подслой. ОПУСТИТЬ если нет)
├── primer                      (Mesh — праймер/грунт)
└── substrate                   (Mesh — основание бетон/стяжка)
```

- **Никаких дополнительных детей** в plateRoot.
- **Y вверх**, +Z к зрителю, +X вправо.
- Origin plateRoot — в центре верхней грани topcoat, на y=0. Все слои — НИЖЕ y=0.

### Материалы (Material slots в Blender)

Каждая mesh имеет **один материал** с именем, точно повторяющим имя меша + префикс `VAR_` для топкоата:

- `topcoat` mesh → material name `VAR_topcoat` (важно! `VAR_` префикс — JS свапает материал на этом ключе)
- `body` mesh → material name `body`
- `mesh-layer` mesh → material name `mesh-layer fibreglass`
- `membrane` mesh → material name `membrane`
- `primer` mesh → material name `primer`
- `substrate` mesh → material name `substrate`

### Запреты

- **НЕ** запекать освещение в текстуры. Освещение даёт сам движок (HDR-environment + directional).
- **НЕ** добавлять брэнд-логотипы Sika / других производителей. Это серая зона по правам.
- **НЕ** использовать subdivision modifier выше уровня 1 на финальном меше (избыточно для квадратной плиты).
- **НЕ** оставлять n-gons (только tris и quads).
- **НЕ** добавлять анимацию внутри GLB (explode-эффект делает движок отдельно через position interpolation).
- **НЕ** упаковывать текстуры внутрь GLB как embedded — текстуры идут отдельно (см. раздел 3).
- **НЕ** добавлять collision / physics / armature / shapekeys / drivers — это статическая mesh.
- **НЕ** менять имена объектов и материалов. Один таййо в имени = плита не загрузится.

Текстуры **не идут с GLB**. Заказчик собирает реальные фото своих укладок в папке `~/Desktop/floor-materials-library/0X-<material>/1-finish/` (10 материалов). Каждая папка содержит close-up фактуры (1024×1024 минимум).

**Тебе от текстур нужно только:**
1. Правильно развернуть UV (см. раздел 6).

3. В финальном GLB **только UV-координаты**, без embedded image references. Движок подгрузит текстуры по slug имени.

## 5. ОТСТУПЫ СЛОЁВ (wedding-cake step) — для explode-вида

В текущей модели каждый нижний слой чуть меньше верхнего (внутрь на 1-2 мм по периметру). Это сохранить — позволяет в explode-виде видеть «торт». Формула:

- topcoat: 300×300 (полный)
- body: 299×299 (-0.5 мм по стороне)
- mesh-layer (если есть): 298.5×298.5
- membrane (если есть): 298×298
- primer: 297.5×297.5
- substrate: 297×297

**Все слои строго центрированы по X/Z** (origin посередине).

## 6. UV-РАЗВЁРТКА

### Topcoat и Body — критично

UV должен быть таким, чтобы при tiling=1 ОДИН размер плитки = ОДИН модуль реальной фактуры:

- Для terrazzo (камень 4-18 мм) на плите 300×300 мм → tile=1 даёт 1 «единицу» = 300 мм. Реальная крошка должна выглядеть размером ~4-18 мм. Так что UV сделать так, чтобы tile-параметр в JS (`def.tile` в manifest) контролировал повторение. **UV-острова прямоугольные, не растянутые.**
- Для microtopping (хаотичная микро-фактура) — UV 1×1 = 300×300 мм, в JS будет tile=2-3 для повторения.
- Для rubber (видимая EPDM крошка 1-4 мм) — tile=4-6 ожидается, UV должен это выдержать без растягивания.

### Substrate

Substrate — снизу, не виден кроме как в explode/layers view. Можно UV нативно из geometry, бетонная текстура.

### Edge tiling

Боковые грани **не должны** иметь видимых seams. Сделать ровную UV-распаковку 4 боковых граней + торца (как у мебели с фанеровкой).

## 7. ГЕОМЕТРИЯ — детали для каждого слоя

### Topcoat

- Просто плита 300×300×{thickness} mm с фаской 1.5-2 мм сверху и снизу
- 1 уровень subdivision для гладкости

### Body

- Плита {inset}×{inset}×{thickness}
- Если материал зернистый (terrazzo, rubber) — НЕ модельте крошки геометрией. Это даст текстура.
- Если массивный (decorative-concrete) — body берёт ~60% высоты плиты

### Mesh-layer (только microtopping)

- Тонкая сетка 0.3 мм. Можно сделать **очень тонким plane** с текстурой fiberglass-cross-weave
- ИЛИ моделить как реальную сетку (массив тонких цилиндров крест-накрест). Второй вариант красивее но heavier. Первый ОК.

### Membrane (только comfortfloor)

- Плита {inset}×{inset}×5mm
- **Можно дать лёгкий «пористый» feel** — например, через очень слабый bumpscale в normal или edge bevel. Так пользователь поймёт что это амортизирующий слой.
- Цвет — серый/желтоватый/recycled (бледный)

### Primer

- Тонкая плита 0.15-0.8 мм
- Без деталей, просто слой

### Substrate

- Плита {inset}×{inset}×{thickness}
- Текстура — серый бетон, шершавый
