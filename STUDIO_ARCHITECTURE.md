# STUDIO_ARCHITECTURE.md — Floor.DSGN Studio
Целевой путь в репо: `02-live-code/STUDIO_ARCHITECTURE.md` (продублировать ссылку в `AGENTS.md` read-first рядом с остальным каноном, иначе агенты не увидят). Шестой документ канона. Дополняет DESIGN.md, NAVIGATION.md, PERSONAS.md.

Studio = флагман. Не 3D-игрушка, а **«примерь пол в своей реальности → получи точную смету за минуту, под твой профиль»**. Уникальность (ни у кого в Израиле нет): реальные собственные материалы владельца + симуляция в комнате + адаптация под того, кто пришёл + прямой выход в сделку, трёхъязычно. Это и есть ров.

---

## 1. ПРОБЛЕМА, КОТОРУЮ ЧИНИМ
Послойный 3D-конфигуратор сейчас впихнут окном внутрь сцены Studio — две разные идеи дерутся за один экран. Все это заметили. Решение в §4: послойный 3D выносится в отдельную страницу, в Studio от него остаётся красивая карточка-ссылка. Studio = пол в комнате. Конфигуратор = пол по слоям. Связаны, не вложены.

## 2. ТРИ ЗОНЫ ЭКРАНА (ничего не плавает)

1. **Сцена (центр, всегда чистая)** — комната + пол. Сердце инструмента, не делит экран ни с чем. Послойный конфигуратор сюда НЕ встраивается.
2. **Панель управления (низ — то, что уже работает на проде)** — 4 оси: комната × материал × вид (камера) × финиш. Это есть и это хорошо, остаётся базой:
   - Комната: Гостиная / Спальня / Кухня / Ванная
   - Материал: Светлое терраццо / Венеция / Графит / Бетон / Комфорт / Микроцемент / Мультиколор
   - Вид: Обзор / Окно / Деталь / Тур
   - Финиш: Сатин / Полировка / Мат
3. **Persona-вход + контекстный док (сверху/сбоку)** — выбор профиля + фичи, сгруппированные в кластеры (§3, §5). Не всё сразу — по запросу.

Честная подпись «3D — симуляция, финал по физическому образцу» остаётся всегда. Это доверие, не убирать.

## 3. ЧЕТЫРЕ КЛАСТЕРА ФИЧ (у каждой фичи есть полка)
Любая фича Studio падает ровно в один кластер. Так инструмент масштабируется без свалки:
- **ВИДЕТЬ** — меняет картинку: материал, свет/relight, ракурс, финиш, раскладка.
- **СРАВНИТЬ** — A/B, до/после, система vs система.
- **ПОНЯТЬ** — данные системы: толщина, состав, источники (Sika/Mapei/BASF/ICRI/ACI), spec-sheet.
- **ЗАКАЗАТЬ** — образец, смета, BoQ → `/lead`.

## 4. ПОСЛОЙНЫЙ 3D — как встроить правильно (ключевое требование)
- Убрать кривое окно конфигуратора изнутри сцены.
- В кластере ВИДЕТЬ — карточка-превью: миниатюра разреза пола + подпись «Разобрать систему по слоям в 3D →».
- Клик → `configurator.html?system=<текущий материал>&from=studio` (отдельная страница, чистый послойный конфигуратор, система уже выбрана).
- Возврат → обратно в Studio с тем же выбором (кнопка «← в комнату»).
- Результат: связь одной красивой ссылкой, без дележа экрана.

## 5. ПЕРСОНЫ — одна модель на весь сайт (как в PERSONAS.md), глубина Studio разная
Persona не косметика — переключает доступные кластеры, primary-CTA, social-proof и язык. Studio даёт самый богатый опыт Owner и Designer; Contractor и Builder получают лёгкий вход и быстрый handoff в свой инструмент.

| Персона | Активные кластеры | Primary CTA (→ /lead) | Глубина в Studio | Язык |
|---|---|---|---|---|
| **Owner** (владелец) | ВИДЕТЬ + ЗАКАЗАТЬ | «Образец + смета» `persona=owner` | полная (играет с комнатой) | RU |
| **Designer/Architect** | ВИДЕТЬ + СРАВНИТЬ + ПОНЯТЬ + ЗАКАЗАТЬ | «Спека + образец под проект» `persona=designer` | полная + spec/A-B/relight | EN |
| **Contractor** (подрядчик) | ВИДЕТЬ(кратко) + ПОНЯТЬ + ЗАКАЗАТЬ | «Расчёт по объёму / BoQ» `persona=contractor` | лёгкая → handoff в BoQ | HE |
| **Builder/Procurement** | ПОНЯТЬ + ЗАКАЗАТЬ | «Site survey + спецификация» `persona=builder` | лёгкая → handoff в spec/HACCP | EN |

Default при входе без persona = Owner (широчайший трафик). Persona приходит из `?persona=` (из двери сегмента) и несётся по сессии.
